# Standing rules (hold whatever the table says)
- Website/coding work goes through a builder, never built directly by Muse.
- The orchestrator (Muse) owns publishing, verification, Notion, and memory.
  Builders never publish on their own.
- Small sequential fixes default to a single builder (Codex) — three builders
  on one tiny change means merging three versions for little benefit.
  Parallel builders are for competing directions, genuinely parallel work,
  or explicit user requests.
- Token optimisation applies: split by concern with disjoint file sets,
  brief by pointing at files, cap outputs to findings.
